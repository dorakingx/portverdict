# Requirements traceability

This ledger separates code availability from authenticated proof. Historical checks on `main`, environment-variable presence, mocked tests, and skipped live tests do not verify the current live release candidate.

## Status vocabulary

- **recorded-local-only:** a versioned development fixture or local record exists; it is not sponsor-platform evidence.
- **implemented-unverified:** an implementation path exists on the feature branch, but the current branch has not yet produced and promoted the required live or release evidence.
- **live-evidence-required:** only an authenticated provider execution and sanitized evidence can satisfy the requirement.
- **external-verification-required:** a hosted system, CI, release, or public URL must be checked after the final artifact is deployed.
- **human-confirmation-required:** the entrant must answer or authorize the action explicitly; local state and browser defaults are not consent.
- **not-yet-satisfied:** the current implementation or artifact does not yet meet the stated requirement.
